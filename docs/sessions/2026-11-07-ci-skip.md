## Constraints and settled decisions
- Reading of her words: whole runs repeat trees already tested (reading a). "When to skip" points there. Making each run cheaper (reading b) is listed under Out.
- Inert paths (out of the fingerprint): `.claude/`, `docs/sessions/`, `docs/review/`, `docs/phases/`, `CLAUDE.md`, `README.md`, `docs/PRD.md`, `docs/BUILD_PLAN.md`, `docs/THIRD_PARTY.md`. When in doubt a path stays in. `docs/contract/` (schema read by `tools/ci/test_schema_agreement.py`) and `docs/validation/` (read by `tools/validation`) stay in.
- Skipped jobs (job-level `if`) report "skipped", which GitHub counts as passing for required checks; workflow-level `paths-ignore` is not used because it leaves required checks pending.
- Merge to `main`: Actions caches from a PR are not visible on `main`. A plan-only merge has the fingerprint of `main`'s previous commit, so it skips against `main`'s own marker (runs 90, 92 would have been skipped). A merge that changes code gets a full run on `main`, which also keeps `main`'s build caches warm.
- A marker kept alive by repeated hits can outlive the 90-day artifact retention of the run it links; then a full run is forced by `force` or a code change. Rare; noted, not handled.
