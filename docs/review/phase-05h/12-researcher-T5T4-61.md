**Project code facts (read; they are what the host facts land on)**

- **C1** `SpatialSceneProcessor::reset()` → `pipeline_.reset()` → `resetSequence(!nonRealtime_)` → `quiesceBuilder()` (`IrBuilderThread::quiesce` blocks on `cv_.wait(lock, !busy_)` until the running build observes the cancel flag) → `decide(Source::ResetStep3)` → if the built IR set is not current, `solveAndBuild(scene, ResetStep3)` → gate class `Synchronous` → `sim::buildRoomIR` on the calling thread. `PluginProcessor.cpp` L141–144; `ScenePipeline.cpp` L313–316, L245–265, L166–199, L115–133; `IrBuilderThread.cpp` L44–50. Confirms ledger T5T4-59 ("ResetStep3 can build").
- **C2** `setNonRealtime(true)` → `resetSequence(false)` (same blocking quiesce) ; `setNonRealtime(false)` → `restartBuilder()`. `ScenePipeline.cpp` L318–327. Called by the JUCE VST3 wrapper from `setupProcessing` (UI thread) and from every `processAudio` (processing thread; no-op when unchanged) — F6; by the AU wrapper from the property setter's thread — F7.
- **C3** The debug guard `realtimeProcessDepth` marks only the realtime branch of `process()` (`ScenePipeline.cpp` L440–457); the offline branch's `decide(Source::Offline)` runs on whatever thread delivers the `kOffline` block. The plug-in has no API-level way to know whether that thread also serves the host's live graph (F3, F4).
