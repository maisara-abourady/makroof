## 3. Not found
- Any primary or developer-forum statement that Live, Logic, Cubase/Nuendo, Bitwig, REAPER, Studio One/Fender or Pro Tools issues `setProcessing(false)`/`reset()` from the audio thread. Searched: forums.steinberg.net, sdk.steinberg.net (503), forum.juce.com, KVR, Cockos, Image-Line, Steinberg dev-portal FAQ/call-sequence, SDK audiohost; terms: setProcessing, reset, transport stop, bypass, flush, suspend, render thread.
- Logic's `AudioUnitReset` timing/thread: lists.apple.com coreaudio-api archive returned 502 on two attempts (2005/Feb/56, 2008/Oct/225, 2010/Feb/93, 2022/May/0); web.archive.org blocked. Search snippets (unverified) say Logic resets on timeline changes, not reliably on stop.
- Steinberg forum post claiming a UI/audio thread split with `setProcessing(false)` on the audio thread: not located in any thread I read (201851, 892085, 965623, 785558, 1015586 contain no thread assignment).
- What settles it: the instrumented per-host build (file 12 §3) logging thread id per `reset()`/`setNonRealtime` call.

## 4. Conflicts
- Spec permits `setProcessing` on the processing thread (file 12 F1–F2) vs. every open-source host read (JUCE's own hosts, Ardour, Carla, SDK audiohost) issuing it only from lifecycle/activation paths, and Arne Scheffler (F11) seeing no transport-triggered suspend. Not a contradiction; a permission versus observed practice.

## 5. Seat claims screened
None assigned for RQ-H3-3. Decider's premise "JUCE-based hosts inherit the wrapper behaviour": **confirmed with a qualification** (F1–F2): they inherit a `reset()` that also toggles `setActive`, but no JUCE-shipped host calls it on any thread.
