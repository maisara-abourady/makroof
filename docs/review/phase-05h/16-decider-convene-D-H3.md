**A code fact the seats need (from `test_diffuse_gate.cpp` L306–310, L354):** the probe's criterion is *bit difference of the IR with FTZ off vs on, both without the guard*. It detects a denormal only where flushing it changes an output bit; a denormal that arises and is flushed without changing the IR bits is invisible to it. So the probe's negative result shows "no denormal that matters to the IR", not "no denormal arose". The premise "asserted to produce denormals" could still be tested directly through the FPU's denormal-operand status flag (x86 MXCSR DE bit; AArch64 FPSR IDC) or an `fpclassify` sweep of intermediates; that is a Seat 5 / Seat 2 question below. The probe ran on one box (Linux, Release); D2 (fp-contract off, `/fp:precise`) is what makes a cross-OS difference in denormal production unlikely, but the probe has not run on macOS / Windows.

**Origin:** Seat 5's re-run note (interrogator file 8 L62: "the test room must produce denormals without FTZ"; decider file 10 L101); Seat 2 (file 3 L74: "compute the referral in double, or flush, so it cannot produce denormals") — the double sums the row requires may be why no denormal reaches the IR.
